Parse · slot compare

design study · diff visualisation

The current compare view prints two rows of plain text and lets the officer scan for divergences character by character. Three patterns below replace that with a token-level diff. The vocabulary is the same in all three: washed crimson, struck through for what one slot omitted, a celadon underline for what the other added. Whitespace differences carry a small · mark so they're never invisible.

i.

In-row strip — replaces the “+ compare” link

expand-in-place

Default state collapses into the existing field row. When the officer expands a disagreeing field, both slot values appear with token-level highlight; the right gutter shows a single  δ  with a count. Designed for short fields (party names, dates, currencies) where stacking is overkill.

ii.

Stacked compare — for the right panel

replaces CompareModeTable

Per-field card. Consensus on top in warm paper; each slot below with its diff rendered against the consensus, not against each other. For long-form fields (goods description, conditions text) the diff renders as a single flowing block — divergent words pop out without forcing eye-pingpong.

iii.

Correction popup — “model got it wrong”

CorrectionModal.jsx

The popup shows a slot picker (radio per slot, one click adopts that slot verbatim), the diff against the current consensus, the verbatim raw_quote from the document with page number, and a free-text override input for cases where neither slot is right.

α

Where the diff is computed

In the UI. The diff npm package (≈ 5 KB gzip) is the only dependency. diffWordsWithSpace for prose, diffChars for ids and amounts. Field values are short enough that O(mn) is invisible — typical render is sub-millisecond per row.

Backend already returns the raw material at /sessions/{id}/documents/{docId}/extracts — the per-slot map plus consensus plus raw_quote provenance. No new endpoint, no new event, no schema change. The diff lives entirely in CompareModeTable.jsx and CorrectionModal.jsx.

Tokenization picks itself up from the field’s declared type in field-pool.yaml: AMOUNT / DATE / CURRENCY_CODE / INTEGER → diffChars, everything else → diffWordsWithSpace. The same mapping decides whether to render in mono or serif.
